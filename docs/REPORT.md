## 三、三个具体障碍

### 障碍 1：写路径在 .NET 侧被拒（主要缺口）

| 场景 | 结果 |
|---|---|
| Python 读写打开 | ✅ 12/12 成功 |
| .NET 只读打开 | ✅ 稳定成功 |
| .NET 读写打开 | ❌ `ERROR_ACCESS_DENIED` (5) |

**权限层面是允许的**（Python 已证明），但从 .NET 进程发起读写打开会被拒。
推测与 .NET 请求的附加访问位有关，尚未定位。

> **重要更正**：早期曾错误判定为「管道 ACL 只授予读权限」。后续用
> 「逐例隔离 + 重试」重测后推翻 —— 当时的错误 5 是连续探测时句柄竞争造成的假象。

**客户端已实现降级**：先试读写，失败退回只读，永不崩溃。

### 障碍 2：网卡启停需要管理员权限

```powershell
Disable-NetAdapter -Name "Radmin VPN" -Confirm:$false
# → Access is denied.
```

当前用户 `冯乐潇` 不是管理员。这是 Windows 的设计，无法从用户态绕过。

### 障碍 3：UI 自动化路线不可用

官方 GUI 是 Qt5 应用，未启用无障碍桥接。即使设置 `QT_ACCESSIBILITY=1` 重启，
UI Automation 树仍为 **0 个元素**，无法用于代驱动。

## 六、关键技术发现

1. **分层架构**：Qt5 UI ↔ SYSTEM 服务 ↔ 云端；控制面与数据面分离
2. **控制管道**：`\\.\pipe\RadminVpnGuiChannel`，支持多客户端并发
3. **线格式**：`[len:u32 LE]` + 自描述 TLV 记录流（类型 1 字节 + 字段号 2 字节）
4. **状态推送**：连接后主动推送全量快照（约 206 KB），之后是增量事件
5. **传输层**：ENet（UDP 可靠传输），失败回退 TcpRelay
6. **后端**：`radminte.com` 域名池，含 23 个中继节点候选
7. **官方支持代理**：注册表有 `ProxyServers` / 服务器地址，二进制含
   `ProxyLogin` / `ProxyPassword`
