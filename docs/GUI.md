# RvpnKit GUI —— 跨平台图形客户端

用 Avalonia 写的桌面客户端，**同一份代码、两个后端**：

```
rvpnkit-gui
  ├─ DirectControlService   ← 进程内直连命名管道，走 RvpnKit.Core
  │                            没有 HTTP、没有 JSON、没有中间进程，延迟最低
  │                            仅 Windows
  └─ HttpControlService     ← 走 rvpnkit-agent 的 REST
                               任何平台、任何机器都能用
```

启动时自动选择：Windows 上先探测管道，能连就直连；否则回退到 agent。
状态栏右下角会显示当前用的是哪个后端。

## 运行

```powershell
# Windows：直连（推荐，最快）
src\RvpnKit.App\bin\Release\net10.0\rvpnkit-gui.exe

# 指定 agent（跨平台/远程）
rvpnkit-gui.exe --agent http://192.168.1.10:8770 --token <令牌>

# 也可以用环境变量
$env:RVPNKIT_AGENT='http://127.0.0.1:8770'; $env:RVPNKIT_TOKEN='xxx'
```

## 功能

| 区域 | 操作 |
|---|---|
| 顶部 | VPN 总开关、修改本机别名、刷新 |
| 左栏 | 网络列表（含成员数）、按名字加入、创建网络、选中网络的启用/禁用/离开/删除 |
| 右栏 | 成员列表（节点 ID / 别名 / 公网 IP）、踢出 / 授予管理员 / 撤销管理员 / 批准加入 |
| 底部 | 公共网络搜索 + 一键加入（双击结果也行） |

## 只读模式

如果状态栏显示「只读」，说明管道只能只读打开。原因是**进程完整性级别**：
受限环境（某些沙箱、以低权限被拉起的子进程）运行在 `Low`，而 Radmin 控制管道
要求 `Medium` 才允许写入。

此时所有写操作按钮会被禁用。用普通用户身份直接双击运行即可恢复正常。

## 技术取舍

- **界面用 C# 代码构建，不用 XAML**。少一层 XAML 编译器，构建失败面最小，
  代价是界面代码比 XAML 稍长。
- **不用 MVVM 框架**。这个界面状态简单，直接 code-behind + 手动刷新更直观，
  也少一个依赖。
  （`IControlService` 这一层抽象是为了双后端，不是为了 MVVM。）
- **命令后主动刷新**。写入后立即 `RefreshAsync(force:true)`，让界面马上反映
  真实状态，而不是本地乐观更新 —— Radmin 的状态最终以服务端为准。

## 已知问题

- **GUI 进程必须重定向标准输出才能从脚本启动**：直接 `Start-Process` 会让
  父 shell 等它的 stdout 关闭而卡住。从资源管理器双击不受影响。
- `app.manifest` 如果写得不合规会导致 `side-by-side configuration is incorrect`
  启动失败。当前已移除该文件（.NET 程序默认可跑）。
