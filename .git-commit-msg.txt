feat: 打通 IP 与别名识别 —— 成员列表可显示身份

这是本项目最关键的能力补全：现在能回答「哪个 IP 是谁」。

问题
- 网卡邻居表有虚拟 IP 和 MAC，但没有身份
- 服务日志有节点 ID、别名、连接方式，但没有 IP
- 两者此前是割裂的两张表

突破（实测确认的三条规律）
1. 虚拟 IP 在控制管道快照里以 4 字节原始形式出现
   （26.169.61.178 → 1a a9 3d b2），每个 IP 约出现 2 次
2. 别名以 UTF-16LE 出现，且起点可能是奇数对齐
   —— 早期只按偶对齐扫描，导致别名几乎全部漏检
3. 同一条节点记录内别名与 IP 相距 100~170 字节，但 delta 分布不单峰，
   因此纯邻近配对不可靠

采用的强判据
- 以服务日志中的已知别名作白名单，只接受在流中精确命中的别名文本
- 再与邻近 IP 配对，剔除由二进制块误解码产生的假别名
- 双向去重：同一别名只归属距离最近的 IP

验证（三重）
- 映射规模：440 条关联（白名单 1585 个别名）
- 唯一性：无重复别名，严格一对一
- 稳定性：连续 3 次独立采集，250/250 条共有映射 100% 一致，零漂移

新增
- src/RvpnKit.Client/AliasResolver.cs   IP 与别名解析器（含设计注释）
- 三种输出模式（默认报告 / --json / --list）统一展示身份
- --json 新增 stats.identifiedPeers / pipeBytes / pipeFrames
- 采集逻辑抽为 CollectBindingsAsync，三种模式共用
